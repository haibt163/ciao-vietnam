# Ciao Vietnam — Project Instructions

## 1. Project Identity

**Ciao Vietnam!**

Repository: `haibt163/ciao-vietnam` (public)

Canonical integration branch: `main`. `main` is the protected source of record.
Normal implementation work uses a dedicated feature branch or worktree.

---

## 2. Product

A mobile-first, app-like travel guide for foreign visitors to Vietnam. It is a
promotion campaign built by AI agents and a showcase of AI-built UI.

- Vision: "Lonely Planet 2.0 × Claude Code" — image-first, keywords over long
  text, warm paper/charcoal look, terminal motifs used sparingly.
- Audience: travellers on phones (iOS and Android). Desktop is secondary.
- No database, no login, no accounts, no backend.
- English by default, Vietnamese by automatic browser detection. Mandarin is a
  possible later addition and is NOT built now.

---

## 3. Technology Stack

Pinned. Do not upgrade or add dependencies without a short justification in the
handoff.

- Next.js 16.4.0 (App Router), React 19.3.0, TypeScript
- Tailwind CSS 4 (`@tailwindcss/turbopack`)
- `motion` 14.0.0 (animation), `lucide-react` 1.52.0 (icons)
- Fonts through `next/font/google`: Fraunces (display), Be Vietnam Pro (body),
  IBM Plex Mono (labels)
- `sharp` (dev only, image preparation), native Web Audio for sound
- Node `22.x` (matches Vercel; `engines` in `package.json` and `.nvmrc`)

Canonical dependencies and scripts are defined by `package.json`.

Not used, and not to be added without approval: database, auth, CMS, API
routes, server state, analytics/trackers, GSAP, three.js, an i18n framework, a
state library, a search library, an offline service worker.

---

## 4. Application Boundaries

Everything is generated at build time (static). Preserve the separation between:

- routes and layout (`app/`);
- UI components (`components/`);
- content as typed JSON (`content/`);
- helpers (`lib/`);
- build/prep scripts (`scripts/`);
- documentation (`docs/`).

One shared region view renders every region from a data file. A new region must
need zero code changes.

---

## 5. No Database, No Authentication

Do not add a database, accounts, login, cookies for identity, or any
server-side state. Browser `localStorage` is used only for the visitor's own
preferences: language, theme, sound.

---

## 6. Content Model

- `content/regions/<slug>.json` — one file per region (hero, lede, chips, Don't
  miss, Sights, Eat, Stay, Getting there).
- `content/images.json` — every photo: `id`, `src`, `srcSet`, `width`, `height`,
  `alt` {en, vi}, `credit`, `license`, `licenseUrl`, `source`, optional `focus`,
  `heroLayout`, `cropped`.
- `content/home.json`, `content/ui.json` — Home and interface strings.
- `content/search.json` — generated by `scripts/build-search.mjs` during
  `prebuild`. Do not hand-edit.
- Every visible string is `{ en, vi }`.

---

## 7. Content Provenance and Text Rules

The two reference guidebooks are Lonely Planet Vietnam (16th ed.) and DK
Eyewitness Vietnam. They are reference material only.

- The books are kept outside the repository and are never committed.
- No sentences are copied. Copy is original, keyword style: chips, 3–7 word
  bullets, "Don't miss / Best for / When / How to get there".
- Places and chapter placement follow the books. Every factual claim should be
  traceable to a book chapter; record this in `docs/sources.md`.
- Anything not traceable is removed or listed as UNVERIFIED in `docs/sources.md`.
- Reader-friendly choices that differ from the books (for example Ninh Binh on
  the North Vietnam page) are stated plainly in `docs/sources.md`.
- Region names: Hanoi, North Vietnam, Central Vietnam, Southeast Coast (search
  alias "South Central"), Central Highlands, Ho Chi Minh City, Mekong Delta
  (Phu Quoc and Con Dao are sections of this page), Siem Reap & Angkor
  (labelled Cambodia).

---

## 8. Images and Licensing

- Images are NOT taken from the two guidebooks. They come from properly
  licensed sources.
- Allowed licenses: CC0, public domain, CC BY, Unsplash License, Pexels License.
- Not allowed: CC BY-SA (excluded until a clear reading of the adaptation rule
  is recorded in `docs/photo-selection.md`), any NonCommercial (NC), any
  NoDerivatives (ND).
- Every photo has credit, license, license URL and source in `images.json`. The
  credits page (`/credits`) is generated from it and states that images are
  resized and, where `cropped` is true, cropped.
- Quality bar for an original: at least 3000 px on the long edge (2400 px
  absolute minimum), sharp, well exposed, clear light. Reject hazy, grey,
  low-light snapshots, watermarks, banners, readable brand signs.
- Hero images are portrait-cropped from the original with a per-photo `focus`.
  Never upscale. If a source is too small, set `heroLayout: "landscape"`.
- Compression: WebP, quality floor 78 for heroes and 75 for cards.
- Selection decisions and rejections are logged in `docs/photo-selection.md`.
- Owner-supplied photos are welcome; record the photographer and page URL.

---

## 9. Design and Experience

- Light (warm paper) and dark (charcoal) themes with one warm clay accent.
- Image-first cards, tap targets at least 44 px, thumb-zone bottom tab bar,
  safe-area insets, no hover-only interactions.
- Keywords over paragraphs; about 40 words visible per section at most.
- Parallax hero and entrance animation respect `prefers-reduced-motion`.
- Sound: tiny tap sounds, unlocked on first tap, low volume, persisted mute
  toggle, never autoplay.
- Page content must be visible without JavaScript (server HTML must not hide
  content with `opacity:0`).
- No Claude or Anthropic logos or mascot.

---

## 10. Mobile and Performance

- Design at 390 px width; check 360, 390 and 430 px.
- No horizontal scroll; readable text; responsive `srcset` for every photo;
  lazy-load everything except the first hero.
- Total `public/images` under 40 MB.
- Lighthouse results are only reported if actually run, and are labelled as
  sandbox or live.

---

## 11. Language

- English default. First visit: detect `navigator.languages`; `vi` selects
  Vietnamese. EN | VI toggle in the header, persisted.
- A Vietnamese phone must not flash English before switching (inline boot
  script sets the language before first paint).
- Vietnamese strings are marked for native review in `docs/vi-review.md`.
- Place names with Vietnamese diacritics are written correctly.
- Adding Mandarin later means adding a language key and a font, not new code.

---

## 12. Practical Information Accuracy

- Prices, opening hours and distances from print guides are dated. Pages say
  "verify locally" instead of showing them as current.
- Visa, entry, currency and health rules change. Do not state specifics unless
  checked against an official source and dated; otherwise keep it general and
  tell the reader to verify before travel.

---

## 13. Production Runtime

- Deployed to Vercel from GitHub (preview per branch).
- No environment variables are required. Do not introduce undeclared ones.
- Builds need network access to Google Fonts. A sandbox without it cannot run
  `next build` unchanged; record this when reporting.
- Image preparation (`scripts/images.mjs`) needs the original photos, which are
  not in the repository; it exits cleanly when they are absent.

---

## 14. Verification

Canonical scripts are defined by `package.json`:

- `npm run typecheck`
- `npm run lint`
- `npm run build` (runs `scripts/build-search.mjs` first; commit
  `content/search.json` if it changed)

For UI changes also report, with real output or screenshots:

- 390 px screenshots (light and dark, EN and VI) of changed pages;
- no horizontal scroll and tap targets of at least 44 px;
- content visible with JavaScript disabled;
- no language flash on a Vietnamese browser.

Do not claim a command passed without executing it. Anything that could not be
run is UNVERIFIED.

## 16. Multi-Lane Engineering Model

Lanes: Claude Code, Codex CLI/App, OMP CLI, Grok (sandbox), and a chat lane
acting as author in two-lane mode (Claude Chat or ChatGPT). Sandbox lanes
without Git write access (Grok, chat lanes) deliver a ZIP or patch plus
plain-language steps and a pull-request description; the Project Owner commits
and pushes. Lane choice does not change scope, verification, Git rules, review
or approval boundaries, or the Project Owner's final authority.

---

## 17. Approval Boundary

Project Owner defines task → implementation → tests + evidence + handoff →
Chief Engineer review (APPROVE / REQUEST CORRECTION) → APPROVE from Claude Chat,
ChatGPT or the Project Owner → merge executed by the Project Owner, Claude Code
or Codex CLI/App → protected `main`.

The author never approves their own change. Grok, OMP and chat lanes do not
execute merges. See `docs/ENGINEERING_GOVERNANCE.md` §6a.

---

## 18. Scope Control

A task produces the smallest correct change. Do not combine unrelated
refactors, dependency changes, redesigns, content rewrites or architecture
changes with a scoped task unless explicitly authorized. Record newly
discovered unrelated issues separately.

---

## 19. Definition of Done

A substantive task is complete when:

- the authorized scope is implemented;
- relevant verification has been run and reported with real output;
- every photo has recorded credit, license and source;
- no book text or book image is in the change;
- important claims are evidence-backed or labelled UNVERIFIED;
- the diff is focused and reviewable;
- documentation is accurate where behavior changed (and `docs/HANDOVER.md` is
  updated);
- remaining limitations are explicit;
- the work is ready for the required review.
